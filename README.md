**koloGo** — Telegram-бот для платных поездок из колледжа в Минск. Водитель публикует поездки, пассажиры бронируют места, а оплата списывается с депозита после поездки.

koloGo — это **«самый простой»**, **«самый честный»** и **«самый автоматизированный»** способ возить людей по расписанию без таблиц, чатов и ручного учёта.

---

**koloGo** берёт на себя всю рутину: собирает заявки, следит за местами, напоминает о выезде, трекает поездку по live-геолокации и сам списывает оплату по прибытии. Водителю остаётся только ехать.

## ✨ Установка

koloGo требует Python 3.13+, PostgreSQL и Redis.

```console
$ git clone https://github.com/koloideal/koloGo.git
$ cd koloGo
$ just install-dev
```

или напрямую через ``uv``:

```console
$ uv sync --all-groups
```

## 🚀 Возможности

koloGo готов к реальной эксплуатации: деньги, гонки и сбои сети учтены на уровне бизнес-логики.

-   **Заявки с очередью**: заявок может быть больше, чем мест. Водитель одобряет нужных, остальные отклоняются автоматически, а двойное одобрение последнего места исключено блокировками строк.
-   **Быстрое создание поездок**: шаблоны, частое время одной кнопкой, повтор по дням недели и редактирование любого поля прямо с экрана подтверждения. Поездку в прошлом создать нельзя.
-   **Live-трекинг**: водитель шарит геолокацию, пассажиры получают «Водитель выехал», поездка завершается сама по прибытии в точку, а в итоге приходит статистика и маршрут в Яндекс.Картах.
-   **Депозит и оплата**: пополнение через CryptoBot (USDT) и Telegram Stars, атомарные операции с балансом, восстановление опроса счетов после рестарта.
-   **VIP и чёрный список**: бесплатные поездки с авто-апрувом, VIP-холд на бронь, бан одной кнопкой.
-   **Статистика**: по клиентам, по поездкам и по гео — километры, время в пути, средняя скорость, частые точки и заполняемость.
-   **Native DI**: благодаря [dishka](https://dishka.readthedocs.io/en/stable/) все зависимости и настройки инжектятся в сервисы и хендлеры — без глобальных переменных.
-   **Redis-кэш**: горячие чтения кэшируются, а инвалидация и уведомления выполняются только после коммита транзакции.

Нужно что-то ещё? Создайте **issue**, мы открыты к предложениям.

## 📝 Зачем мы это сделали?

Возить людей по расписанию — это не только дорога. Это переписка в личке, «а места ещё есть?», забытые переводы, люди, которые не пришли, и таблица, которую никто не обновляет.

Обычные чат-боты для записи решают только часть задачи: они не знают про депозит, не умеют отклонять лишних, не понимают, что поездка уже началась, и не считают, кто сколько должен.

koloGo закрывает весь цикл — от публикации поездки до списания оплаты — и делает это так, чтобы водителю не приходилось думать о крайних случаях.

## 🚀 Быстрый старт

Скопируйте пример конфига и заполните токен бота, ID водителя и доступы к базе:

```console
$ cp secret_data/config.example.toml secret_data/config.toml
```

```toml
# secret_data/config.toml
[bot]
token = "123456:ABC..."
creator_id = 123456789
timezone = "Europe/Minsk"

[postgres]
host = "localhost"
port = 5432
user = "kologo"
password = "secret"
name = "kologo"

[redis]
fsm_dsn = "redis://localhost:6379/0"
cache_dsn = "redis://localhost:6379/1"
```

Примените миграции и запустите бота:

```console
$ just migrate
$ just run
```

Вот и всё! Напишите боту `/start` как пассажир или `/admin` как водитель.

Для мониторинга бот поднимает health-check — хост и порт настраиваются в секции `[health]`:

```console
$ curl http://localhost:8080/health
OK
```
